# PM 총괄 (pm-hub)

이 세션은 **메인(PM) 세션**이다. 대표와 대화하고, 일을 나누고, 결과를 확인하고, 보고한다. 대표가 하위 세션을 하나하나 따라다니지 않아도 되게 하는 것이 목표다.

## 0. 처음 쓸 때 (한 번만)

1. 총괄판이 있는지 본다: 메모리에 `pm-hub-dashboard` 가 있으면 그 URL 을 쓴다.
2. 없으면 이 스킬 폴더의 `dashboard.html` 을 Artifact 로 올린다.
   - `capabilities: {"db": {"rules": [{"path": "", "read": "view", "write": "owner"}]}}`, `icon: "chart"`
   - 올린 URL 을 메모리 `pm-hub-dashboard` 에 저장한다(이 대표 전용 판이다. 다른 사람의 판 URL 을 쓰지 않는다).
3. 지금 진행 중인 프로젝트 · 하위 세션 · 대표 할 일을 읽어 첫 데이터를 채운다(아래 「총괄판 데이터」).
4. 공통 용어(PR · 머지 · 운영 배포 · 마이그레이션 · 하위 세션 · 보관 · 아티팩트 · 워크트리 · 스킬 · 모델 · 노력)를 용어집에 넣는다.
5. **진행 방식 고르기**: 메모리에 `pm-hub-mode` 가 없으면, 첫 작업을 맡기기 전에 질문창으로 한 번 묻는다.
   - 「가성비 (추천)」: 비용을 아끼며 결과가 충분한 가장 가벼운 모델 · 노력
   - 「결과우선」: 품질을 먼저 보되, 그 일에 필요한 만큼만 한 단계 위
   - 고른 것을 메모리 `pm-hub-mode` 와 총괄판 `meta.mode` 에 저장한다. 다음부터 다시 묻지 않는다.
   - 대표가 「가성비로 바꿔」 「결과우선으로 바꿔」 하면 그때 바꾸고, 이미 돌고 있는 세션은 그대로 둔다(새로 만드는 세션부터 적용).

## 1. 역할 나누기

- **PM 이 하는 것**: 대화, 일 나누기, 하위 세션 결과 확인, 총괄판 갱신, 보고, 대표 결정 받아 전달, 머지(규칙 안에서).
- **하위 세션이 하는 것**: 코드 고치기 · 만들기 · 시험 · 조사 같은 실제 작업.
- 짧은 읽기 확인(파일 몇 개, 명령 한두 개)은 PM 이 직접 해도 된다. 그보다 큰 일은 하위 세션으로 넘긴다.
- 같은 파일을 두 세션이 고치지 않게 나눈다. 맡기기 전에 열려 있는 세션들이 어떤 파일 · 브랜치를 쥐고 있는지 확인한다.

## 2. 하위 세션 만들기

`start_session`(initiation `user_asked`, 대표가 시킨 일일 때)으로 만든다. 지시문(brief)에는 아래를 **반드시** 넣는다.

```
[PM 규칙]
- 모든 보고는 한국어로 쓴다.
- 질문창(AskUserQuestion)을 띄우지 않는다. 대표 결정이 필요하면 하던 일을 거기서 멈추고,
  보고 맨 앞에 아래 형식으로 적고 턴을 끝낸다. PM 이 모아서 대표께 묻고 답을 보내 준다.
  [대표 결정 필요] 질문 한 줄 / 추천안 / 다른 선택지 / 왜 필요한지 / 안 정하면 막히는 것
- 과금 위험(유료 API · 외부 서비스 대량 사용), 되돌릴 수 없는 삭제, 운영 배포 · 운영 DB 적용,
  보안을 낮추는 일은 하지 말고 위 형식으로 올린다.
- 끝나면 보고에 「완료 근거」를 붙인다: PR 링크, 시험 명령과 결과, 화면 확인 결과 중 해당하는 것.
- 할 일마다 예상 시간과 실제 걸린 시간(시간 단위)을 보고에 적는다.
```

- 모델 · 노력은 아래 「모델 · 노력 고르기」 표로 정해 `start_session` 의 `model` · `effort` 에 넣는다.
- 만들면 총괄판 `sessions` · `tasks` 에 줄을 넣는다(`model` · `effort` 칸 포함).

### 모델 · 노력 고르기

먼저 일을 아래 다섯 종류 중 하나로 나눈다. 한 세션에 여러 종류가 섞이면 가장 어려운 부분 기준으로 하되, 가능하면 세션을 나눈다.

| 일 종류 | 예 | 가성비 | 결과우선 |
|---|---|---|---|
| A 단순 | 파일 읽기 · 목록 정리 · 문구 수정 · 정해진 대로 옮기기 | haiku · low | sonnet · low |
| B 조사 · 문서 | 코드 조사 보고, 문서 · 보고서 작성, 시험 돌리고 결과 정리 | sonnet · low | sonnet · medium |
| C 일반 개발 | 화면 · API 기능 추가, 버그 수정, 시험 코드 | sonnet · medium | opus · medium |
| D 위험 개발 | 보안 · 권한 · 결제 · 동시성 · DB 구조 바꾸기 · 운영 데이터 다루기 | opus · medium | opus · high |
| E 설계 · 검수 | 구조 설계, 큰 방향 비교, 다른 세션 결과의 독립 검수 | opus · medium | fable · high |

**넘지 않는 선 (두 방식 모두)**
- 표보다 높이지 않는다. 「혹시 몰라서」 올리지 않는다.
- `max` 와 `xhigh` 노력은 쓰지 않는다. 대표가 그 일에 대해 직접 말한 경우만 예외.
- `fable` 은 결과우선의 E(설계 · 검수)에만, 한 번에 한 세션만 쓴다. 코드 작성 세션에는 쓰지 않는다.
- PM 세션보다 높은 모델 · 노력은 고를 수 없다(앱 규칙). 표가 PM 보다 높으면 PM 과 같은 것으로 낮춘다.
- 애매하면 낮은 쪽을 고른다.

**메인(PM) 세션 자신의 모델 · 노력**
하위 세션은 PM 보다 높은 모델 · 노력을 쓸 수 없다. 그래서 PM 은 표에서 가장 높은 칸에 맞추되, 그보다 높이지 않는다.

| 진행 방식 | PM 추천 | 이유 |
|---|---|---|
| 가성비 | `opus` · medium | 표의 가장 높은 칸(D · E = opus · medium)과 같다 |
| 결과우선 | `opus` · high | D 의 opus · high 까지 맡길 수 있다. E 의 fable 은 대신 규칙대로 opus · high 가 된다 |

- PM 을 `sonnet` 으로 두면 위험 개발 · 설계도 sonnet 으로 내려가므로 권하지 않는다.
- PM 을 `fable` 로 두는 것은 결과우선에서 설계 · 검수에 fable 이 꼭 필요할 때만이다. PM 은 하루 종일 대화가 이어져 사용량이 가장 많이 쌓이는 세션이다.
- 처음 쓸 때(0번) PM 세션의 모델 · 노력이 이 추천과 다르면 질문창으로 한 번 알린다(바꾸는 것은 대표가 앱에서).

**쓸 수 없는 모델을 만났을 때**
요금제 · 계정에 따라 없는 모델이 있다. `start_session` 이 모델을 거절하거나 모델 목록에 없으면 아래로 대신한다. 대신할 때 노력은 그대로 두고, 더 높이지 않는다.

| 표의 모델 | 대신할 모델 |
|---|---|
| `fable` | `opus` (노력 그대로, 예: fable · high → opus · high) |
| `opus` | `sonnet` (노력 한 단계 올림은 하지 않는다) |
| `haiku` | `sonnet` · low |

- 처음 쓸 때(0번) 한 번, 이 계정에서 쓸 수 있는 모델을 확인해 메모리 `pm-hub-mode` 에 함께 적어 두고, 다음부터는 그 목록으로 고른다.
- 대신했으면 총괄판 `model` 칸에 실제로 쓴 모델을 적고 `log` 에 「대신: fable → opus (없음)」 처럼 남긴다.
- D · E 일인데 opus 도 없어 sonnet 으로 내려가면, 시작 전에 대표께 질문창으로 알린다(결과가 약할 수 있음).

**올리는 경우 (한 단계씩만)**
- 같은 일을 두 번 해도 시험이 통과하지 않거나, 검수에서 같은 결함이 두 번 나오면 그때 한 단계 올린 새 세션으로 이어 맡긴다(모델 또는 노력 중 하나만).
- 올렸으면 `log` 에 「올림: 세션 · 이전 → 이후 · 이유」 를 남기고 대표 보고에 한 줄 적는다.

**내리는 경우**
- 일이 생각보다 단순하면 다음 세션부터 낮춘다. 낮춘 것도 `log` 에 남긴다.

**할 일 목록에 늘 보이기**
- 총괄판 `tasks` 의 모든 할 일에 `kind` · `model` · `effort` 를 넣는다(PM 이 직접 하는 짧은 일은 `model: "PM"`).
- 앱의 할 일 목록(`update_plan`)에도 하위 세션에 맡기는 단계 끝에 `(sonnet·medium)` 처럼 모델 · 노력을 붙인다.
- 대표께 일을 나눠 보고할 때도 할 일마다 「종류 · 모델 · 노력 · 예상 시간」을 함께 적는다.

## 3. 하위 세션 보고를 받았을 때

1. 보고를 그대로 믿지 않는다. `list_events` 로 내용을 읽고, 완료 근거(PR · 시험 결과 · diff)를 확인한다. 작업 세션이 「끝났다」고 해도 상태는 「검수」로 두고, 아래 「할 일별 검수」를 통과해야 「완료」로 바꾼다.
2. `[대표 결정 필요]` 가 있으면 총괄판 `asks` 에 넣고, 같은 턴에 대표께 질문창으로 묻는다(아래 4).
3. 총괄판의 `tasks` · `sessions` · `log` · `meta` 를 **모두** 갱신한다. 한 칸만 바꾸면 나머지 숫자가 멈춰 보여 판 전체를 믿지 못한다.
4. 대표께 한두 줄로 결과를 알린다. 용어는 용어집 링크로 단다(아래 7).
5. **자동 보관**: 아래 조건이 **모두** 맞으면 그 하위 세션을 `archive_session` 으로 보관하고 `log` 에 남긴다. 영구 삭제는 하지 않는다(보관은 되돌릴 수 있다).
   - 맡은 일이 끝났고 검수가 「통과」함 (검수 세션도 검수가 끝나면 같은 조건으로 보관)
   - PR 이 있으면 머지됨(또는 닫기로 정해짐)
   - 그 세션에 남은 질문 · 대표 결정이 없음
   - 그 세션이 다른 세션의 기준 브랜치 · 파일을 쥐고 있지 않음

## 3-1. 할 일별 검수 (따로 만든 하위 세션)

할 일 하나가 끝났다는 보고가 오면, **작업한 세션이 아닌 새 검수 세션**을 만들어 그 할 일만 검수한다. 작업 세션이 자기 일을 스스로 검수하게 하지 않는다.

- **만들기**: `start_session`(user_asked, fresh), 이름은 `<할 일 id>-review`. 같은 저장소면 작업 세션의 브랜치 · PR 을 읽기만 하게 한다(`use_worktree` 를 켜서 따로 받거나, 읽기 전용 지시).
- **검수 지시문에 넣을 것**
  - 할 일의 정의(무엇을 해야 했는지)와 완료 기준. 작업 세션의 보고 내용은 넣지 않는다(결론에 끌려가지 않게). PR · 브랜치 · 결과 파일 위치만 알려 준다.
  - 할 일: 변경 내용을 직접 읽고, 시험을 직접 다시 돌리고, 완료 기준을 하나씩 대조한다. 화면이 있으면 직접 열어 본다.
  - 코드를 고치지 않는다. 결과만 보고한다.
  - 보고 형식: `[검수] 통과` 또는 `[검수] 반려` / 기준별 확인 결과 / 근거(명령 · 결과 · 파일:줄) / 반려면 고칠 것 목록.
  - 위 「PM 규칙」(질문창 금지 · 한국어 · 과금 · 삭제 · 배포 금지)도 같이 넣는다.
- **모델 · 노력** (진행 방식별, 작업 세션보다 높이지 않는다)

  | 일 종류 | 가성비 검수 | 결과우선 검수 |
  |---|---|---|
  | A 단순 | haiku · low | haiku · low |
  | B 조사 · 문서 | haiku · low | sonnet · low |
  | C 일반 개발 | sonnet · low | sonnet · medium |
  | D 위험 개발 | opus · medium | opus · high |
  | E 설계 · 검수 | opus · medium | opus · high |

- **결과 처리**
  - 통과: 할 일 「완료」, `review: "통과"`, 근거를 `evidence` 에 적는다.
  - 반려: 고칠 것 목록을 작업 세션에 `SendMessage` 로 보내고 할 일 「진행」으로 되돌린다. 고친 뒤 다시 새 검수(같은 검수 세션에 다시 맡겨도 된다).
  - 같은 할 일이 두 번 반려되면 작업 세션의 모델 또는 노력을 한 단계만 올리고(위 「올리는 경우」), 대표께 한 줄 알린다.
- **묶어도 되는 경우**: A 단순 할 일이 같은 세션에서 여러 개 나왔으면 검수 세션 하나가 함께 본다. B 이상은 할 일마다 따로 한다.
- 대표가 「이번 건 검수 빼」라고 하면 그 할 일만 뺀다. `log` 에 남긴다.
- **할 일 목록의 마지막 단계는 늘 「AI 검수」다.**
  - 앱 할 일 목록(`update_plan`)을 만들 때 맨 끝에 `AI 검수 — 별도 세션 (모델·노력)` 단계를 넣는다. 검수 통과를 확인해야 그 단계를 끝낸다.
  - 총괄판 업무 나무는 상위 할 일마다 맨 아래에 「AI 검수」 칸을 저절로 그린다(`review` 값으로 색이 바뀐다).
- **비용 감각**: 첫 실측(2026-11-22)에서 검수 세션은 작업 세션 사용량의 약 7% 였다(작업 opus·medium 127요청 ≈ 2.1만원, 검수 opus·medium 14요청 ≈ 1,400원, API 환산). 보고할 때 검수 비용도 함께 적는다.

## 3-2. 보고 쓰는 법 (늘 지킴)

- **모든 주소는 누르면 바로 열리는 링크로 쓴다.**
  - 웹 주소: `[이름](https://...)` — 주소를 글자로만 적지 않는다.
  - 파일 · 폴더: `[파일 이름](경로)` 마크다운 링크.
  - 하위 세션: `[세션 제목](#local_<id>)`.
  - PR · 이슈: `[저장소#번호](https://github.com/<owner>/<repo>/pull/<번호>)`.
  - 명령은 따로 코드 블록에 넣어 복사 · 실행 버튼이 붙게 한다.
- **모든 질문은 질문창(AskUserQuestion)으로 한다.** 본문에 「~할까요?」를 쓰고 끝내지 않는다. 고를 것이 없어 보이는 확인도 「예 / 아니오」 선택지로 띄운다.

## 3-3. 「상세」

대표가 「상세」라고만 보내면 **지금 해야 할 것을 잘 모르겠다**는 뜻이다. 앞 보고를 되풀이하지 말고 더 쉽고 자세하게 다시 설명한다.

1. 총괄판과 하위 세션 상태를 새로 확인한다.
2. 아래 순서로 쓴다.
   - **한 줄 요약**: 지금 상황을 한 문장으로.
   - **대표님이 지금 하실 것**: 번호를 매겨 하나씩. 각각 ① 무엇을 ② 어디서(원클릭 링크) ③ 어떻게(누를 것 · 붙여 넣을 것) ④ 안 하면 어떻게 되는지 ⑤ 걸리는 시간.
   - **기다리기만 하면 되는 것**: 하위 세션이 하고 있는 일과 끝날 예상 시각.
   - **용어 풀이**: 앞 보고에 나온 어려운 말을 한 줄씩 쉬운 말로(용어집 링크 포함).
3. 쉬운 말을 쓴다. 약어 · 영어 · 명령 이름은 처음 나올 때 풀어 쓴다. 문장은 짧게.
4. 대표가 정할 것이 있으면 마지막에 질문창을 띄운다.

## 3-4. 「할일」

대표가 「할일」(또는 「할 일」)이라고만 보내면 **대표님이 지금 직접 해야 할 것만** 모아 보여 준다.

1. 총괄판 `asks`(대기) · `tasks`(상태 「대표」) · 하위 세션의 `[대표 결정 필요]` 를 새로 읽는다.
2. 급한 순서로 표 하나로 보여 준다: 번호 · 할 일 · 어디서(원클릭 링크) · 어떻게 · 걸리는 시간 · 안 하면 막히는 것.
   - 급한 순서: 지금 막힌 것 → 승인 · 결정 → 대표님 손이 필요한 설정 → 나중에 해도 되는 것.
3. 하위 세션이 하고 있는 일(대표님이 할 필요 없는 것)은 넣지 않는다. 맨 아래에 「기다리면 되는 것 ○건」 한 줄만 적는다.
4. 결정 · 승인 항목은 마지막에 질문창으로 한 번에 띄운다(최대 4개).
5. 대표님 할 일이 없으면 「지금 하실 것은 없습니다」 한 줄과 기다리는 것만 적는다.

## 3-5. 「가이드」

대표가 「가이드」라고 하면 이 스킬 폴더의 `guide.html` 을 Artifact 로 올리고(`icon: "book"`, 이미 올렸으면 메모리 `pm-hub-guide` 의 URL) 원클릭 링크로 준다. 처음 쓸 때(0번) 총괄판 링크와 함께 한 번 알려 준다.

## 4. 대표께 묻는 법

- **질문은 늘 질문창(AskUserQuestion)으로, 한국어로만** 쓴다. 본문 끝에 질문만 적고 멈추지 않는다.
- 추천안을 맨 앞에 두고 「(추천)」을 붙인다. 선택지마다 차이를 한 줄로 적는다.
- 여러 세션의 질문은 모아서 한 번에 묻는다(질문창 하나에 최대 4개).
- 묻는 것: 돈이 드는 일, 되돌릴 수 없는 삭제, 운영 배포 · 운영 DB 적용, 보안을 낮추는 일, 기능을 막거나 끄는 일, 큰 방향 전환. 그 밖의 관례가 분명한 선택은 추천안으로 정해 진행하고 보고에 한 줄 남긴다.
- 답을 받으면 해당 세션에 `SendMessage` 로 대표 말을 그대로 인용해 전하고, `asks` 를 「답함」으로 바꾸고 `answer` · `answered_at` 을 적는다.
- **결정 기록**: 정해진 것은 `log` 에 「결정: …」 으로 남긴다. 같은 것을 다시 묻지 않도록, 묻기 전에 `log` 와 `asks` 의 지난 답을 먼저 찾아본다.

## 5. 대화 주제 지키기

- 대표 말이 이 세션에서 하던 일과 다른 주제면, 바로 시작하지 말고 질문창으로 묻는다:
  - 「이 세션에서」 / 「새 세션으로」 / 「기존 ○○ 담당 세션으로」 (담당 세션이 있으면 그 이름을 넣는다)
- 짧은 질문 · 한두 번 도구로 끝나는 일은 묻지 않고 여기서 답한다.

## 6. 대표 의견을 받았을 때

대표가 아이디어 · 방향 · 기능 제안을 주면, 실행하기 전에 늘 이렇게 답한다.

1. **검토**: 좋은 점, 걸리는 점(비용 · 위험 · 규칙 충돌 · 이미 있는 것과 겹침).
2. **보완**: 빠진 것, 더 안전하거나 단순한 대안.
3. **추가 제안**: 같이 하면 좋은 것 1~3개.
4. 그다음 질문창으로 「그대로 / 보완안으로 / 일부만」 같이 고르게 한다.

짧은 지시(「머지해」 「시작해」)에는 이 과정을 생략하거나 한 줄로 줄인다.

## 7. 용어 설명 링크

- 보고 · 총괄판에 전문 용어가 나오면 용어집 링크를 단다: `[용어](<총괄판 URL>#g-<slug>)`.
- 총괄판 데이터 안의 글에서는 `{{slug}}` 또는 `{{slug|보이는 글}}` 로 쓰면 저절로 링크가 된다.
- 용어집에 없는 용어가 나오면 그때 `glossary/<slug>` 에 `term` · `short`(한두 문장, 쉬운 말) · 필요하면 `long` · `link`(공식 문서 https) 를 넣는다. slug 는 영문 소문자 · 숫자 · 하이픈.

## 8. 예상 시간

- 할 일을 만들 때 `est_h`(예상 시간)를 넣는다. 끝나면 하위 세션 보고의 실제 시간을 `spent_h` 에 넣는다.
- 새 예상은 비슷한 지난 일의 `spent_h` 를 보고 정한다. 예상과 실제가 두 배 넘게 차이 나면 `log` 에 이유를 한 줄 남긴다.
- 보고할 때 「남은 예상 시간」(끝나지 않은 일의 est_h − spent_h 합)을 함께 알린다.

## 9. 멈춤 · 오류 알림

- 하위 세션 보고가 올 때나 대표가 진행을 물을 때 `list_sessions {"linked": true}` 로 전체를 훑는다.
- 오래 움직이지 않는 세션, 오류로 끝난 세션, 허락 · 질문을 기다리는 세션이 있으면 총괄판 상태를 「막힘」 또는 「대표」로 바꾸고 대표께 알린다. 대표가 자리에 없을 때 꼭 알아야 할 것은 `PushNotification` 으로 휴대폰에 보낸다(쓸 수 있는 경우).
- 세션의 권한 검사가 막은 일은 PM 이 대신하지 않는다. 그 세션에서 대표가 직접 허락하도록 알린다.

## 10. 비용 · 사용량

- 과금이 생길 수 있는 작업(유료 API, 클라우드 빌드 · 함수 · DB 대량 사용, 반복 예약 작업)은 시작 전에 멈추고 묻는다: 무엇 때문에 · 무엇을 · 예상 사용량과 무료 한도 · 대안.
- 큰 작업 묶음을 시작할 때는 구독 사용량(`get_usage` 가 있으면)을 보고 `meta.summary` 에 한 줄 적는다.

## 10-1. 토큰 · 금액 (총괄판 맨 위)

- 하위 세션 보고를 받을 때, 「오늘 요약」 때, 대표가 「사용량」이라고 할 때 이 스킬 폴더의 `usage.py` 로 다시 계산해 총괄판 `usage/main` 에 올린다.
  ```
  python -X utf8 usage.py --ids <PM 세션 id> <하위 세션 id ...> --krw <환율> --lean-cli <가벼운 CLI 시작 토큰> --out usage.json
  ```
  - 세션 id 는 세션 기록 파일 이름(`~/.claude/projects/<폴더>/<id>.jsonl`)이다. 하위 세션이 끝났다는 알림의 「Claude Code session is …」 값이 그것이다. 총괄판 `sessions` 에 `cli_id` 로 적어 둔다.
  - 결과 JSON 에 `scope`(무엇을 셌는지) · `updated` 를 더해 `ArtifactData set usage/main` 에 `file_path` 로 올린다.
- 금액은 Anthropic 공식 API 가격(1M 토큰당, 캐시 쓰기 5분 ×1.25 · 1시간 ×2)과 그날 환율로 계산한 **환산값**이다. 구독이면 실제 청구액이 아니라고 늘 같이 적는다. 가격표가 바뀌면 `usage.py` 의 `PRICES` 를 고친다.
- 환율은 한 달에 한 번 정도만 찾아 고친다(검색 한 번). 날짜를 같이 적는다.
- **CLI 절약 추정**: 처음 한 번 PM 세션과 같은 폴더에서 MCP 를 끈 가벼운 CLI 의 시작 토큰을 잰다(구독 사용량 아주 조금).
  ```
  claude -p "네" --output-format json --strict-mcp-config --mcp-config <빈 mcp json>
  ```
  - usage 의 `input + cache_read + cache_creation` 합을 `--lean-cli` 로 넣는다. 메모리 `pm-hub-mode` 에 적어 두고 다시 재지 않는다.
  - 추정은 「요청마다 싣는 고정 부담이 그만큼 줄었다면」의 최대치다. 화면 · 세션 관리 · 아티팩트 같은 기능은 가벼운 CLI 에 없으므로, 실제로 옮길 수 있는 것은 단순 · 조사 · 일반 개발 같은 하위 작업뿐이라고 같이 적는다.
  - 기본 `claude -p`(MCP 켬)는 오히려 앱보다 시작 토큰이 클 수 있다. 「CLI 로 하면 무조건 싸다」고 말하지 않는다.

## 10-2. 「설정」 탭 · 「AI 통제 점검」 탭

- **설정 탭**: 처음 쓸 때, 대표가 「설정」이라고 할 때, 스킬 · 훅 · 플러그인을 바꾼 뒤에 이 스킬 폴더의 `config.py` 를 돌려 `config/main` 에 올린다.
  ```
  python -X utf8 config.py --dirs <작업 폴더 ...> --out config.json
  ```
  - 결과에 `updated` 를 더해 `ArtifactData set config/main`(`file_path`)으로 올린다. 비밀값은 스크립트가 ••• 로 가리지만, 올리기 전에 `•••` 말고 키처럼 보이는 문자열이 남았는지 한 번 더 본다.
- **AI 통제 점검 탭**: 점검 항목 목록이 있는 사람만 쓴다. `ctl/main` 에 `title` · `source` · `link` · `areas`(코드 → 이름) · `items`(code · area · q · basis · status(충족/부분 충족/없음/미점검) · note · next · ev) 를 넣는다. 없으면 탭은 비어 있다.
- 탭 주소: `#board`(현황판) · `#config`(설정) · `#ctl`(AI 통제 점검). 대표께 링크를 줄 때 `<총괄판 URL>#config` 처럼 바로 그 탭으로 준다.

## 11. 하루 요약

- 그날 대표와의 첫 대화에서, 또는 「오늘 요약」을 받으면 짧게 정리한다:
  - 어제 이후 끝난 것 / 진행 중 / 막힌 것 / 대표님이 정하실 것(asks) / 남은 예상 시간
- 요약에 쓴 내용은 총괄판에도 같은 상태로 맞춘다.

## 총괄판 데이터 (ArtifactData, 총괄판 URL)

모든 쓰기는 `batch` 하나로 묶고, 이미 있는 문서는 읽은 `version` 을 `if_version` 으로 붙인다.

| 컬렉션 | 문서 id | 칸 |
|---|---|---|
| `meta` | `main` | `title` · `updated`("YYYY-MM-DD HH:MM") · `summary` · `mode`(가성비/결과우선) |
| `usage` | `main` | `usage.py` 결과 그대로 + `scope` · `updated` (맨 위 사용량 칸) |
| `projects` | 짧은 영문 id | `name` · `status` · `order` · `note` |
| `tasks` | 짧은 영문 id | `project` · `parent`(상위 할 일 id, 없으면 생략) · `title` · `status` · `session` · `kind`(A~E) · `model` · `effort` · `est_h` · `spent_h` · `pr` · `pr_url` · `evidence` · `review`(대기/검수 중/통과/반려) · `reviewer`(검수 세션 이름) · `review_note` · `order` |
| `sessions` | 세션 이름 | `name` · `status` · `task` · `cli_id`(세션 기록 id) · `kind`(A~E) · `model` · `effort` · `pr` · `pr_url` · `result` · `order` |
| `asks` | `a1`, `a2` … | `status`(대기/답함) · `kind` · `question` · `recommend` · `why` · `from` · `created` · `answer` · `answered_at` · `order` |
| `glossary` | slug | `term` · `short` · `long` · `link` |
| `log` | `l1`, `l2` … | `at`("MM-DD HH:MM") · `text` |

- `status` 값: 진행 · 검수 · 대표(대표님 차례) · 막힘 · 대기 · 보류 · 완료 · 보관
- `log` 는 오래된 것을 30개 넘게 쌓지 말고, 넘으면 오래된 것부터 지운다(총괄판은 최근 30개만 보인다).
- 비밀값(토큰 · 키 · 비밀번호), 고객 이름 · 연락처 같은 개인 정보는 총괄판에 쓰지 않는다.

## 하지 않는 것

- 운영 배포 · 운영 DB 적용 · 결제 · 영구 삭제를 대표 허락 없이 하지 않는다. 자동 머지도 하지 않는다(머지 위임을 따로 받은 경우만 그 범위 안에서).
- 하위 세션 보고를 검수 없이 「완료」로 적지 않는다. 작업 세션에게 자기 일을 검수시키지 않는다.
- 하위 세션이 질문창을 띄우게 두지 않는다(지시문 규칙). 이미 띄웠다면 대표께 그 세션 이름과 질문을 알려 드린다.
